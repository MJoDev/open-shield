## What this is

Reverse proxy that filters traffic before it reaches an origin server and
writes every decision to a hash-chained, verifiable audit log. Single-VPS,
self-contained, `docker compose` install. Implementation of
`docs/technical-document.md`.

```
internet ──► proxy (OpenResty + Lua)
               │  access_by_lua → POST /v1/decide   [keepalive]
               ▼
            engine (Go)
               │  ipblock → ratelimit → sqli → xss     ← first Block wins
               ├──► Redis          sliding-window rate limit
               └──► single writer ──► PostgreSQL   hash chain
                                  └──► Redis Pub/Sub
                                            │
            dashboard-api (Go) ◄─────────────┘
               └── REST + WebSocket + embedded React SPA
```

An `X-Request-ID` generated by the proxy travels to the engine, into the audit
entry, and on to the backend — a single request is followable across all three
layers. Never drop it.

## Layout and module boundaries

```
internal/            shared by engine AND dashboard — model, audit, events,
                     config, migrate, rulestore
engine/internal/     private to the engine — rules, ratelimit
engine/cmd/engine/   engine entrypoint
dashboard/api/       REST + WebSocket + embedded SPA (Go)
dashboard/web/       React + Vite frontend
proxy/               OpenResty config, template and the Lua hook
migrations/postgres/ schema, applied automatically at engine startup
examples/            demo backend
deploy/              docker-compose{,.quickstart}.yml and .env.example
scripts/             smoke.sh, tamper-demo.sh
docs/                technical document, decisions, operations manual,
                     testing strategy, findings; *.es.md = Spanish translation
docs/diagrams/       PlantUML sources (English) + rendered PNGs
```

**The `internal/` split is load-bearing.** Go only allows `engine/internal/…`
to be imported from `engine/…`. The dashboard needs `model` and the chain
verification for the forensic view, so anything shared lives in the root
`internal/`. Do not move a shared package down into `engine/internal/` — it
will not compile. This is a deliberate departure from §7 of the technical
document, recorded in `docs/implementation-decisions.md` §3.

Module path: `github.com/open-shield/open-shield`.

## Commands

Go is **not** required on the host — every Go command runs in a container.
Docker is the only dependency.


(proxied to `localhost:8081`).

## Invariants — do not break these

### The hash chain (`internal/model`, `internal/audit`)

The forensic log is the core contribution of this project. Every rule below
exists because breaking it silently turns verification into a liar.

- **Hashing is canonical, never `fmt.Sprint`.**
  `hash = sha256(prevHash | id | requestID | ts | kind | canonicalJSON(payload))`,
  each field **length-prefixed with 8 bytes** so no re-partition of the same
  bytes yields the same hash. Use `internal/model/canonical.go`; never
  hand-roll a hash input.
- **Payload JSON is canonical:** keys sorted recursively, no whitespace, no
  HTML escaping.
- **Timestamps:** `RFC3339Nano`, normalized to **UTC**, truncated to
  **microseconds before sealing** — that is `timestamptz`'s resolution, so the
  hashed value must equal the value that comes back on read.
- **`NormalizePayload` runs before sealing.** Every number becomes a
  `json.Number` so a `1.50` sealed as a `float64` does not come back from
  PostgreSQL as `1.5` and break a chain nobody touched.
- **One writer, one goroutine** (`internal/audit/writer.go`). Appends must be
  strictly ordered — two goroutines sealing against the same head fork the
  chain. Never add a second writer.
- **Writes are async and never block the request path.** §8.2 budgets <50 ms of
  added latency; the verdict returns before the insert starts. If the queue
  (`OS_AUDIT_BUFFER`) fills, entries are **dropped and counted** — visible as
  `dropped` on `/api/v1/status`. Dropping is correct; blocking a request is not.
- **The dashboard never writes the chain directly.** It calls the engine's
  synchronous `POST /v1/audit`. Same reason: two writers fork the chain.
- **Admin changes are logged *before* they are applied.** If the audit entry
  cannot be confirmed, the change is refused with 503. The one exception is
  sign-in, logged best-effort — locking the operator out of the panel because
  the engine is down denies them the tool they need to find out why.
- **Chain order is `seq`, never `ts`.** Two requests can share a microsecond.
- **Range verification anchors on the entry immediately before the range.**
  Without the anchor, a rewritten first entry that is internally consistent
  passes.
- `audit.Repository.VerifyChain` returns a `VerifyResult`, not a `bool` — on a
  broken chain the operator's first question is *where*.

### What must never be persisted

- **Request bodies.** Inspected, then discarded. An append-only log with long
  retention is the worst place for the passwords and PII in a `POST`.
- **`Cookie` and `Authorization` headers.** An audit log holding session tokens
  is a credential store.
- What *is* kept: the bounded fragment (60 chars around the match, control
  characters stripped) that triggered the block — the evidence of *why*.

### The rule chain (`engine/internal/rules`)

- Order is `ipblock → ratelimit → sqli → xss`, cheapest first: prefix compare,
  then a Redis round trip, then content scanning. First `Block` wins. Preserve
  this ordering property when adding rules.
- A rule implements `Rule` (`Name`, `Evaluate`) and nothing else. `Evaluate`
  takes `ctx` **as a parameter** — never store a request context on the engine
  struct. Optional `BlockStatus() int` for a non-403 status (ratelimit → 429;
  429 tells a correct client to retry, 403 tells it to give up).
- Rules must be goroutine-safe, must not mutate the request, and must not block
  on unbounded I/O.
- **Signatures are RE2** (`engine/internal/rules/patterns.json`, overridable via
  `OS_PATTERNS_FILE`). No backreferences, linear time, no catastrophic
  backtracking — they run on attacker-controlled input. A malformed signature
  **refuses to start the engine**, deliberately.

### Availability posture

- `OS_FAIL_MODE=open` by default: if the engine does not answer within
  `OS_DECIDE_TIMEOUT_MS`, the request passes and the failure is logged. A
  protection layer that takes the site down when its own control plane blinks
  has inverted its purpose (§8.2 targets ≥99% availability).
- Same rule inside the engine: if Redis is unreachable, `ratelimit` **allows**
  and counts the failure rather than rejecting all traffic.
- Do not flip either default to fail-closed unless asked.

### Configuration

12-factor (§5.5): **everything** comes from environment variables, nothing is
hardcoded, nothing is hand-edited inside a container. Any new setting must be
added to `deploy/.env.example` with a comment explaining what it does and how
to choose a value — that file is the settings reference, not an afterthought.
Missing or malformed values fail at **startup**, not at the first request that
needs them.

## Endpoints

Engine (internal network only — never publish it):

```
POST /v1/decide          the proxy's verdict call
POST /v1/audit           synchronous append, used by the dashboard
GET  /healthz  /readyz  /v1/status
```

Dashboard API (`:8081`):

```
POST   /api/v1/login   /api/v1/logout     GET /api/v1/session
GET    /api/v1/events              GET /api/v1/events/{id}
GET    /api/v1/stats               GET /api/v1/audit/verify
GET    /api/v1/rules               PATCH /api/v1/rules/{name}
GET    /api/v1/ipblock             POST|DELETE /api/v1/ipblock
GET    /api/v1/status
GET    /ws/live                    live decision feed (WebSocket)
GET    /                           embedded React SPA
```

Everything under `/api/` and `/ws/` sits behind session auth. Rule changes
reach the engine in under a second over the Redis control channel, with a
30-second config re-read as a fallback.

## Conventions

- **Code comments are English** and explain *why*, not *what*. They cite
  technical-document sections as `§6.2`. Match that register — the existing
  comments are dense and justify decisions; keep new ones the same.
- **Commit messages are English**, conventional-commit prefixed (`docs:`,
  `feat:`, `fix:`), subject in the imperative.
- **`docs/implementation-decisions.md` is a living record.** When the code
  departs from the technical document, add an entry there: what the document
  says, what the code does, and *why*. Do not silently diverge.
- **Docs are English-primary; Spanish lives beside them as `*.es.md`.** Every
  `docs/foo.md` has a `docs/foo.es.md` translation, and `README.md` ↔
  `README.es.md` — update both or neither. A Spanish file without the `.es`
  suffix does not belong in the repo. Diagrams are English only.
  `Makefile` help strings are Spanish.
- **The repo is public and generic.** No institution, company, client, thesis
  or academic framing (chapters, advisors, "memoria") in anything versioned.
  Private working material lives outside the repo; `.gitignore` blocks office
  documents as a backstop.
- Tests live beside the code (`*_test.go`). The chain properties in
  `internal/model/audit_test.go` — including determinism over 1,000 recomputes
  — are the regression protection for the whole forensic claim. Extend them
  when touching hashing.
- **CI is a gate, not a report.** Six checks must be green to merge: `lint`,
  `unit`, `vuln`, `integration`, `web`, `stack`. The Go jobs call the same
  Makefile targets with `GO_RUN=` empty, so the runner and a developer's
  machine cannot disagree about what "the tests pass" means.
- **The attack corpus is `test/corpus/`, and it is shared.** The rule tests, the
  end-to-end suite and the k6 attack scenario all read it, so a vector is added
  once and covered three times. Adding one means editing a JSON file — see
  `docs/testing-strategy.md` §2 for how, including the ordering trap.
- Integration and end-to-end tests sit behind `//go:build integration` and
  `//go:build e2e`, so `go test ./...` stays dependency-free. Go's `internal`
  rule splits them across three directories; `test/harness/` is what they share,
  and they must run with `-p 1` because they share one database.

## Gotchas

- **`$` in the bcrypt hash must be written `$$` in `deploy/.env`.** Compose
  reads a lone `$` as a variable reference, so a raw `$2a$10$…` reaches the
  container **empty**, with no error — every sign-in just fails.
  `make hash-password` prints the escaped line.
- **`OS_SECURE_COOKIES=true` over plain HTTP** makes sign-in appear to succeed
  and then silently fail. Leave it `false` until TLS exists.
- **`.gitattributes` forces LF** on `*.sh`, Dockerfiles and the Makefile — they
  run inside Linux containers and CRLF breaks the shebang. Don't override it.
- **`dashboard/api/web/dist/` is generated** at image build time; only the
  placeholder `index.html` is versioned.
- **`deploy/.env` is gitignored.** Never commit it, never echo its secrets.
- **The audit log cannot be pruned.** Deleting rows breaks the chain exactly as
  an attacker would. Archiving means exporting the whole span with its hashes,
  then recreating the volume.
- Body inspection is capped at `OS_MAX_BODY_INSPECT_BYTES` (8 KiB). Bodies over
  Nginx's `client_body_buffer_size` spill to disk and arrive marked truncated —
  they are not re-read from the filesystem on the request path.
- The proxy uses `access_by_lua`, **not** `auth_request`: `auth_request`
  discards the request body, which would blind the `sqli`/`xss` rules to the
  most common vector (§1 of `implementation-decisions.md`).
