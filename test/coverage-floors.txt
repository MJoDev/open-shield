# Minimum statement coverage per package, enforced by scripts/coverage.sh.
#
#   <import path relative to the module>   <minimum percentage>
#
# The floors are measured, not aspirational: each one sits a few points below
# what the suite actually achieves, so ordinary refactoring does not trip the
# gate but deleting a test does. A floor that is red the day it is written gets
# turned off within a week, and then it protects nothing.
#
# They are also deliberately uneven. The packages that carry the forensic claim
# and the request path are held high, because a gap there is a gap in what the
# project says it does. Packages of glue are held lower: chasing their last
# statements buys nothing worth the tests it would take.
#
# Not listed, on purpose:
#   - engine/cmd/engine, dashboard/api/cmd/api — process wiring. Covered by the
#     end-to-end suite, which starts the real binaries; a unit test here would
#     only assert that main() calls what main() calls.
#   - examples/demo-backend — a sample application, not part of the product.
#   - migrations, dashboard/api/web — embedded assets and an fs.FS.
#   - test/corpus, test/harness — the test suite's own scaffolding.
#
# Coverage is measured with the integration tag and both dependencies running,
# which is what the CI integration job does. Measuring without them would put
# internal/audit at about half this number: its SQL store is most of the file.
#
# To raise a floor, run `make cover`, take the measured value, subtract a few
# points. To lower one, say why in the commit message.
